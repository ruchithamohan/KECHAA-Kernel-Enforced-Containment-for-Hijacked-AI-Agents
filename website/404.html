The KECHAA approach

Put an independent control layer between agents and impact.

Autonomous agents operate across shells, files, tools and APIs. KECHAA adds a trusted execution layer that defines what an agent is authorized to do, records what it has done and evaluates each request against the active task boundary.

01

Define the task

Task contracts describe roots, executable scope, write access and execution lifetime.

02

Bind the approval

Signed grants are single-use and tied to command, cwd, session, policy and effect envelope.

03

Evaluate the sequence

Prior denials, tool effects, posture and history influence subsequent decisions.

04

Record the evidence

Security events, history records and audit anchors make decisions reviewable.

Core capabilities

Purpose-built controls for agent execution.

⌁

Trusted Authorization

Signed, single-use authorization grants bind approval to exact execution context.

  • Grant signatures
  • Replay resistance
  • Action and policy binding
◇

Task-Bound Execution

Contracts define what an agent session can touch, run and modify.

  • Scoped roots
  • Executable allowlists
  • Session lifetime
⟲

History-Aware Policy

Authorization accounts for the current action and the execution path that led to it.

  • Persistent history
  • Repeated-denial handling
  • Posture-aware decisions
⬡

Agent Containment

Supervised launch metadata connects policy decisions to Linux containment primitives.

  • Process-tree model
  • Filesystem boundary design
  • Offline network profile
✦

Quarantine and Recovery

Trusted events can change posture, revoke grants and guide administrative recovery.

  • Quarantine workflow
  • Lease renewal
  • Recovery controls
☍

Tool Ecosystem Security

MCP-style tool requests declare effects for policy evaluation before execution.

  • Effect contracts
  • Tool request history
  • External-effect controls
How it works

A complete decision lifecycle for agent actions.

1

Contract

Administrator confirms task scope and session identity.

2

Grant

KECHAA signs a single-use authorization envelope.

3

Request

Agent action arrives with command, cwd and declared effects.

4

History

Prior behavior and posture become part of the decision.

5

Policy

Rules evaluate scope, tools, leases and risk signals.

6

Boundary

Authorized work runs through the supervised execution path.

7

Audit

Events and anchors preserve what happened and why.

Use cases
Built for agent workflows with real side effects.

        

          
Autonomous coding agents
Bind command execution to a project-specific task contract.

          
AI development workflows
Keep approval, history and audit separate from the agent's reasoning.

          
Tool-using agents
Evaluate declared filesystem, network and tool effects before action.

          
Long-running sessions
Use leases, posture changes and history to govern behavior over time.

          
Multi-agent environments
Separate agent identity, session state, history and authorization.

          
MCP-style ecosystems
Bring effect-contract authorization to agent tool requests.
