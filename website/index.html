Autonomous agent execution security

Your AI agents. Your rules. Your security boundary.

KECHAA puts a trusted local control plane between autonomous agents and real system effects: task contracts, signed single-use grants, history-aware authorization, supervised execution and tamper-evident audit records.

The approach

Authority lives outside the agent.

KECHAA treats an agent action as a security decision, not just a command string. The daemon verifies identity, task scope, policy, action inputs, grant state, runtime posture and previous behavior before a request moves forward.

01

Declare the work

Open a run with a task contract covering roots, executables, write mode and lifetime.

02

Bind the action

Prepare a signed single-use grant bound to argv, cwd, UID, session, policy and declared effects.

03

Remember the path

History, denials, tool requests, posture and leases influence later decisions.

04

Preserve evidence

Audit records, checkpoints and anchors make the control path inspectable.

Capabilities

A control plane built for agent side effects.

01

Task contracts

Administrator-confirmed boundaries for roots, executables, write mode and session lifetime.

02

Signed grants

Ed25519 approval envelopes that bind one action to one policy context.

03

History-aware policy

Previous denials, trusted events, tool requests and run posture shape the next authorization decision.

04

Supervised execution

The daemon hands approved actions to a worker that installs Linux process and filesystem controls.

05

Quarantine + recovery

Trusted signals change posture, revoke outstanding grants and route recovery through administrator action.

06

Tool effect contracts

MCP-style and file-effect requests declare read, write and network effects before approval.

Runtime sequence

One action. Many checks.

The walkthrough mirrors the current control path: a request is scoped by a task contract, checked against policy and history, executed through a supervised worker when approved, and recorded as evidence.
